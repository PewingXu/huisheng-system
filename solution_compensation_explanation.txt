分区补偿替代分区硬度的说明

一、为什么要从“分区硬度”切换到“分区补偿”

1.1 产品落地原因
现有方案里，“分区硬度 Shore A”本质上是在表达：前掌、足弓、后跟三个区域希望有不同的力学响应。但在实际 3D 打印落地时，如果真的按区域做不同硬度，通常会带来以下问题：

1）需要多材料或多工艺切换
不同区域不同硬度，往往不再是单一材料、单一工艺可以直接完成的，容易引入多材料打印、分段打印、后拼接，或者更复杂的参数控制。

2）制造复杂度显著上升
硬度分区意味着打印参数、材料管理、质量控制、工艺稳定性都更难统一，尤其在批量生产时，制造成本和返工风险会明显增加。

3）临床目标并不一定要求“材料硬度分区”
用户真正关心的不是“这个区域 Shore A 是多少”，而是：
- 哪个区域需要抬高支撑
- 哪个区域需要减压让位
- 哪个区域需要增加缓冲承托
也就是说，目标是改变足底受力分布，而不是必须通过“多硬度材料”这一条路径去实现。

所以，从产品工程角度看，分区硬度更像“实现手段的一种设想”，而不是最优的量产参数体系；分区补偿更适合作为真正可制造、可解释、可导出的主参数。


1.2 理论依据：为什么分区补偿可以替代分区硬度
这里的“替代”不是说二者物理意义完全相同，而是说：在鞋垫设计目标上，分区补偿可以替代分区硬度，成为更适合落地的主控制参数。

其理论基础主要有三层：

（一）足底干预的核心目标是“调压”和“重分布载荷”
鞋垫设计的直接目标通常不是改变材料名义硬度，而是改变足底接触形态和受力路径，使局部峰值压力下降，使支撑更合理，使步态中的载荷分布更平衡。

从力学角度看，局部接触压力与以下因素高度相关：
- 局部几何高度
- 接触面积
- 支撑位置
- 结构厚度
- 结构刚度

也就是说，只要能够改变接触几何和支撑分布，就能改变压力分布。分区补偿正是在直接控制“局部几何高度”。

（二）在单材料晶格鞋垫中，几何变化本身就能显著改变等效支撑效果
即使材料不变，只要改变局部厚度、局部抬高量、局部包裹量、局部晶格形状，鞋垫的等效力学响应就会变化。

例如：
- 某区域局部抬高，会更早接触足底，增加该区域承托，起到“增强支撑”的效果。
- 某区域局部下沉或减薄，会推迟接触或降低局部反力，起到“减压让位”的效果。
- 足跟区域增加厚度或保留缓冲，会降低冲击集中。

因此，分区补偿虽然不是直接控制材料模量，但它通过控制几何形态，依然能够达到类似“局部更支撑 / 局部更缓冲 / 局部更减压”的效果。

（三）对 3D 打印鞋垫而言，几何补偿通常比硬度补偿更可制造
对于当前项目的晶格鞋垫模型，系统已经有这些可制造参数：
- 足长
- 足宽
- 足弓矫正厚度 ΔHS
- 基础厚度
- 足跟缓冲厚度
- 晶格体密度

在这个体系里，再引入“分区补偿”，本质上是在现有几何参数体系内继续细化局部调节；而如果继续坚持“分区硬度”，就会把设计逻辑推向多材料/多硬度制造路线。

所以，分区补偿能够替代分区硬度，原因不是“硬度无意义”，而是：
- 对当前产品目标来说，补偿更贴近足底受力重分布这个最终目标；
- 对当前制造方式来说，补偿更容易稳定落地；
- 对当前软件参数体系来说，补偿可以直接接入 3D 几何生成和导出。


1.3 一个更准确的表述
建议把这次切换理解为：
“不是用分区补偿去严格等价替代材料硬度，而是用分区补偿去替代分区硬度，作为智能鞋垫生成系统的主要工程控制参数。”

这在产品定义上更准确，也更容易和制造端对齐。


二、为什么选择 ±1.5mm 作为分区补偿阈值

2.1 代码中的实际定义
当前代码中，分区补偿值最终会被限制在 [-1.5mm, +1.5mm] 范围内：

client/src/components/LatticeInsole3D.tsx

getZoneSupportCompensation(...) 中：
const clampCompensation = (value: number) => Number(Math.max(-1.5, Math.min(1.5, value)).toFixed(1));

这说明 ±1.5mm 不是展示层数字，而是当前实现中的硬限制。


2.2 为什么这个阈值是合理的
就目前代码和产品结构来看，±1.5mm 更像一个“工程安全边界”，而不是一个已经在代码中注明来源的医学金标准。它合理的依据主要有以下几点：

（一）补偿应该是“局部微调”，不能压过主参数
当前鞋垫的主参数仍然是：
- 足弓矫正厚度 ΔHS
- 基础厚度
- 足跟缓冲厚度
- 晶格密度

分区补偿的角色应该是：在这些主参数已经确定后，再对前掌、足弓、后跟做局部微调。
如果分区补偿太大，比如动辄 ±3mm、±4mm，它就不再是“补偿”，而会反过来主导鞋垫几何，削弱主参数体系的层次关系。

±1.5mm 的好处是：
- 足够产生局部受力变化；
- 但又不会盖过主结构参数。

（二）它与当前基础厚度范围是匹配的
当前代码里基础厚度范围是：1.5mm 到 6.0mm。
注意：在代码内部，baseThickness 使用 cm 存储，滑块显示时乘 10 变成 mm。
也就是说，±1.5mm 的局部补偿大致相当于：
- 在最小基厚附近，是较明显但仍可控的调整；
- 在常见 3mm 左右基厚附近，大约是 50% 量级的局部微调；
- 在更厚区域，它只会作为二级修正，不会完全颠覆主体结构。

因此它与当前厚度体系是协调的。

（三）它有利于控制舒适性和制造稳定性
局部补偿过大，容易带来以下风险：
- 局部边界过陡，脚感突兀；
- 某区域过度顶托，引起新的压痛点；
- 减压区域过深，导致结构过薄；
- 晶格顶部曲面变化过猛，影响打印稳定性和强度连续性。

把分区补偿限制在 ±1.5mm，可以把局部形变控制在“明显但不过激”的范围内，更适合当前这个原型的平滑渐变设计。

（四）它和当前可视化/渐变逻辑是一致的
在补偿区域可视化里，颜色强度就是按 1.5mm 这个上限去归一化的：

client/src/components/LatticeInsole3D.tsx
const intensity = Math.min(1, Math.max(0.12, Math.abs(localCompensationMm) / 1.5));

这说明 1.5mm 同时被用作：
- 补偿的幅值上限
- 可视化的强度标尺

从设计一致性上看，这个值已经成为当前系统里“最大有效局部补偿”的统一标尺。


2.3 更严谨的结论
所以，±1.5mm 的理论依据应当写成：

“±1.5mm 是当前系统中为分区补偿设定的工程上限，用于保证补偿是局部微调而不是主结构重写，同时兼顾舒适性、可打印性、曲面连续性以及与基础厚度体系的协调。”

如果未来需要更强的医学证据，需要进一步通过：
- 足底压力复测
- 受试者舒适性评价
- 步态对比
- 打印样件试穿反馈
来校准这个阈值，而不是仅靠代码公式本身证明它是唯一最优值。


三、当前代码中的分区补偿计算逻辑

3.1 输入参数
当前分区补偿的计算函数是：

getZoneSupportCompensation(level, baseThickness, heelThickness, pressureRatio)

位置：
client/src/components/LatticeInsole3D.tsx

输入含义：
- level：足弓等级（1~7）
- baseThickness：基础厚度（cm）
- heelThickness：足跟缓冲厚度（mm）
- pressureRatio：该脚压力占比（0~1）

输出：
- forefoot：前掌补偿（mm）
- arch：足弓补偿（mm）
- heel：后跟补偿（mm）

其中：
- 正值 = 局部抬高 / 增强支撑 / 增强承托
- 负值 = 局部下沉 / 减压让位 / 增强缓冲


3.2 第一步：先把压力占比换算成 pressureBias
代码：
const pressureBias = Math.max(-1, Math.min(1, (pressureRatio - 0.5) / 0.08));

含义：
- 当某只脚压力占比 = 0.5，说明左右脚理想均衡，此时 pressureBias = 0
- 当压力占比高于 0.5，说明这只脚偏重，pressureBias 为正
- 当压力占比低于 0.5，说明这只脚偏轻，pressureBias 为负

除以 0.08 的作用，是把大约 ±8% 的压力偏差映射成 ±1 的标准化偏差，再进行截断。
也就是说：
- 50% ± 8% 以内，系统视为从轻微偏差到明显偏差的连续变化区间；
- 超过这个区间后，不再无限放大，而是封顶到 ±1。

这是一种典型的工程归一化处理。


3.3 第二步：对三区分别计算原始补偿值，再 clamp 到 ±1.5mm
代码：
const clampCompensation = (value: number) => Number(Math.max(-1.5, Math.min(1.5, value)).toFixed(1));

说明：
- 每个区域的补偿值都保留到 0.1mm
- 同时限制在 [-1.5mm, +1.5mm]


3.4 前掌区补偿逻辑
代码：
const forefoot = clampCompensation(
  -0.3 - Math.max(0, pressureBias) * 0.9 + Math.max(0, level - 4) * 0.1
);

拆解如下：

（1）基础项：-0.3
前掌默认略微偏向减压，让前掌不是默认被继续顶高。

（2）如果该脚压力偏高，则进一步减压
- Math.max(0, pressureBias) * 0.9
只有在 pressureBias > 0 时才生效。
也就是：这只脚越重，前掌越倾向负补偿，帮助前掌卸载。

（3）如果 level > 4（偏扁平趋势），会略微往回增加一点支撑
+ Math.max(0, level - 4) * 0.1
level 5/6/7 时分别增加 0.1 / 0.2 / 0.3mm，表示在扁平足趋势下，前掌不能一味减压，还要适度保留支撑连续性。

总体上，前掌区的策略是：
“默认轻度减压；压力越大，减压越明显；但扁平足等级越高，会回补一点支撑，避免前掌完全失去承托。”


3.5 足弓区补偿逻辑
代码：
const arch = clampCompensation(
  (level - 4) * 0.45 - Math.max(0, pressureBias) * 0.15
);

拆解如下：

（1）足弓等级是主导项
(level - 4) * 0.45
- level < 4：结果为负，表示高弓足更倾向减压/让位
- level = 4：结果约为 0，正常足保持中性
- level > 4：结果为正，表示扁平足更倾向抬高支撑

这和足弓设计目标一致：
- 高弓足通常需要避免中足继续受顶压过强，因此足弓区更偏减压；
- 扁平足通常需要增加中足支撑，因此足弓区更偏正补偿。

（2）如果该脚整体压力偏高，会略微削弱足弓区支撑
- Math.max(0, pressureBias) * 0.15
也就是：即使是扁平足，如果该脚整体已经偏重，也不会无限增加足弓支撑，而会适度回撤，避免局部负担过大。

总体上，足弓区策略是：
“以足弓等级为主导，高弓足减压，扁平足支撑，压力偏高时适度回撤。”


3.6 后跟区补偿逻辑
代码：
const heel = clampCompensation(
  (heelThickness >= 20 ? -0.2 : 0.2) - Math.max(0, pressureBias) * 0.85 + (level <= 3 ? 0.25 : level >= 6 ? -0.15 : 0)
);

拆解如下：

（1）先看足跟缓冲厚度
(heelThickness >= 20 ? -0.2 : 0.2)
- 如果足跟缓冲已经比较厚（>=20mm），说明后跟已有较强缓冲，则补偿偏负，避免继续顶高；
- 如果足跟缓冲不大，则补偿偏正，给一点承托。

（2）如果该脚整体压力偏高，则后跟进一步偏向减压
- Math.max(0, pressureBias) * 0.85
说明压力越集中，后跟越应避免继续抬高，转而增加卸载倾向。

（3）足弓等级还会影响后跟策略
+ (level <= 3 ? 0.25 : level >= 6 ? -0.15 : 0)
- 高弓足（1~3）后跟补一点正支撑
- 中重度扁平足（6~7）后跟略偏负补偿

这反映了一个经验性策略：
- 高弓足常伴随局部承托不足，需要后跟更稳；
- 扁平足常更强调整体缓冲和减压，后跟不宜继续过度抬高。

总体上，后跟区策略是：
“先看是否已经有厚缓冲，再看该脚是否偏重，最后再用足弓等级做小幅修正。”


3.7 第三步：分区补偿不是硬分块，而是平滑映射到整个鞋垫表面
虽然参数面板里只显示三个数：
- 前掌补偿
- 足弓补偿
- 后跟补偿

但在 3D 模型里，这三个数不是直接把某个区域整体抬高成台阶，而是通过平滑权重函数分布到鞋垫表面。

核心逻辑在：
- getCompensationZoneWeights(...)
- getLocalCompensationCm(...)
- getInsoleHeight(...)


3.8 区域范围与权重分布
代码中先把鞋垫长度方向归一化为 normalizedZ：
- 0 = 脚跟
- 1 = 脚趾

然后定义三区的大致作用范围：

1）前掌区
normalizedZ 约在 0.58 ~ 0.92 之间
同时横向更强调中部，而不是边缘：
(0.75 + 0.25 * (1 - abs(normalizedX)))

2）足弓区
normalizedZ 约在 0.28 ~ 0.56 之间
同时明显偏向内侧：
(0.4 + 0.6 * max(0, innerSide))

3）后跟区
normalizedZ 约在 0.02 ~ 0.32 之间
同时更强调后跟中心区：
(0.8 + 0.2 * (1 - abs(normalizedX)))

纵向使用的是平滑函数：
createSmoothZoneWeight(value, start, end) = sin(t * π)^2

这意味着每个区域是“中心强、边缘弱、自然过渡”的，不会形成生硬台阶。


3.9 局部补偿是如何加到鞋垫高度上的
代码：
localCompensation =
  forefootCompensation * forefootWeight +
  archCompensation * archWeight +
  heelCompensation * heelWeight

注意内部实际先从 mm 转成 cm，再和鞋垫高度叠加。

鞋垫总高度由这些部分组成：
baseHeight = baseThickness + archHeight + heelCup + heelCushion
adjustedHeight = baseHeight + localCompensation

也就是说，分区补偿不是替代原来的鞋垫高度模型，而是在原有：
- 基础厚度
- 足弓矫正隆起
- 足跟杯
- 足跟缓冲

之上，再叠加局部补偿。


3.10 负补偿还有一个“最小厚度保护”
代码：
const minThickness = Math.max(0.12, baseThickness * 0.55);
return localCompensation >= 0 ? adjustedHeight : Math.max(minThickness, adjustedHeight);

这表示：
- 如果补偿为正，就直接加高；
- 如果补偿为负，就不能无限减薄，至少要保留一个最小结构厚度。

这个保护下限有两层含义：
1）避免减压过度导致局部太薄
2）避免打印结构强度不足或佩戴中塌陷感过强

因此，系统不是“无条件减压”，而是在减压与结构安全之间做平衡。


3.11 分区补偿最终会进入 3D 预览和导出
当前代码里，前掌/足弓/后跟三个补偿值已经不仅仅用于显示，而是实际进入：
- 3D 预览几何生成
- STL 导出
- GLB/GLTF 导出

也就是说，它们已经是实质性的打印参数，而不是说明性文字。


四、结论

4.1 关于为什么从分区硬度切换到分区补偿
因为当前产品真正要控制的是足底受力重分布，而不是展示一个理论上的多硬度分区；在 3D 打印量产场景下，分区补偿比 Shore A 分区硬度更可制造、更可解释、更容易直接进入几何建模与导出流程。

4.2 关于为什么是 ±1.5mm
当前代码中的 ±1.5mm 是一个工程上限，用来保证分区补偿是局部微调，而不是主结构重写；它与现有基础厚度范围、舒适性需求、结构连续性和打印可行性是匹配的。

4.3 关于当前补偿计算逻辑
当前逻辑是一个“经验型规则模型”：
- 以足弓等级决定主要支撑/减压方向
- 以左右脚压力占比决定是否进一步卸载重压脚
- 以后跟缓冲厚度决定后跟区是否还需要额外承托
- 最后将三区补偿通过平滑权重映射到整个鞋垫曲面
- 对负补偿设置最小厚度保护

这套逻辑已经足够支持当前原型系统和打印导出，但如果未来要作为正式医学或工业参数标准，仍建议通过样件测试、压力复测和试穿反馈做进一步标定。
